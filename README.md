## 1. 项目总览与工程目录结构

本项目基于魔兽争霸III经典 8 人常规对战地图 `(8)feralas.w3x`，在保持四族经典对战建筑、兵种、科技树平衡的基础上，重构注入了全新的自定义高机制英雄、全套配套技能与克隆体系、智能双层测试模式（Test Mode Dialog）、沙盒测试假人指令（`-spawn`）以及自主行动的战略级电脑 AI（Strategic Army Commander）。

## 2. 自动化构建与重构流水线

当对代码 (`war3map.j`) 或对象 (`build_v13_objs.py` / `*.ini`) 做出更改后，必须按以下标准流水线执行构建与部署：

### 步骤 1：JASS 语法编译检查 (Syntax Check)
魔兽争霸 III 引擎对 JASS 语法极其敏感，任何语法错误都会导致进入游戏提示“无法读取地图”。我们使用内置的 `pjass.exe` 结合 Patch 1.32.8 现代 API 库进行静默编译验证：
```powershell
Set-Location "C:\Users\wyh\.gemini\antigravity\scratch\feralas_hero"
& tools\JassHelper\pjass.exe tools\w3x2lni\data\zhCN-1.32.8\mpq\Scripts\Common.j tools\w3x2lni\data\zhCN-1.32.8\mpq\Scripts\Blizzard.j payload\war3map.j
```
*必须看到输出 `Parse successful: ... payload\war3map.j` 且 `0 errors`。*

### 步骤 2：对象数据编译 (Object Compilation)
若修改了技能数值、说明文本或单位属性，运行：
```powershell
python tools/build_v13_objs.py
```
该脚本会将 `factory_tpl/table` 的 INI 文件通过 `w2l.exe` 编译并自动提取最新的 `war3map.w3a` 和 `war3map.w3u` 到 `payload/` 目录。

### 步骤 3：一键 MPQ 打包构建 (`do_rebuild.ps1`)
运行一键打包脚本：
```powershell
powershell -ExecutionPolicy Bypass -File do_rebuild.ps1
```
> **注意**：由于 `StormLibSharp.dll` 是 32 位二进制文件，`do_rebuild.ps1` 内部已固定调用 `C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe`，切勿在外部强制以 64 位环境反射调用 `StormLibSharp`。

### 步骤 4：部署至魔兽争霸游戏目录
```powershell
Copy-Item rebuild_feralas.w3x "C:\Users\wyh\Documents\Warcraft III\Maps\Download\(8)feralas.w3x" -Force
```

## 4. 英雄 1：幻梦大师 (`H002`) 机制与 JASS 架构

### 4.1 镜像与潜行 (`A001` + `A00V` + `DM_StealthLoop`)
- **双重保命与刺客机制**：施法时基于 `AOmi` 生成分身混淆视听，同时通过底层马甲向施法者施加 `A00V` 隐身。
- **高频潜行监测 (`DM_StealthLoop`)**：由 0.05 秒高频计时器驱动。若施法者已学习大招 `A004`，潜行状态下强制将其移速提升至引擎极限 **522.0** (`SetUnitMoveSpeed`)。
- **破隐一击背刺 (`DM_BreakInvisibility`)**：通过 `EVENT_PLAYER_UNIT_DAMAGED` 监测，若英雄处于潜行中发起普攻，会瞬间破隐并附加背刺暴击伤害与特殊音效。

### 4.2 幻梦奴役 (`A002` + `DM_CastPossession` + `DM_CapTimerLoop`)
- **超维度强控**：能接管普通野怪、高级兵种甚至敌方英雄与建筑。
- **防止侵入玩家祭坛的死亡回退机制 (`DM_OnUnitDeath`)**：

### 5.5 v2.9 魔音忍者分身无限增殖恶性 Bug 根因剖析与彻底修复
在多名电脑/玩家同时使用魔音忍者（如 7 电脑混战）时，曾出现分身呈指数级几何倍增（7 → 14 → 28 → 56……击杀超千单位）的严重问题。在 **v2.9** 中已完成地毯式排查与根治：
- **Bug 根因深度剖析**：
  1. **分身阵亡传染因果印记（死循环链式反应）**：原 `DM_OnUnitDeath` 第 2 节判定中，分身（`u002`）与神尊（`u001`）阵亡时也会向击杀者施加 `A013` 因果印记。多忍者混战中分身相互击杀，导致大量分身带上印记；当带印记单位被击杀时又触发第 3 节重生，衍生出无穷无尽的分身。
  2. **Lv3 印记 1 变 2 双倍裂变**：原第 3 节中存在 `if klv >= 3 then Ninja_SpawnClone(..., +45.0)` 逻辑，使得高级印记每次触发直接生成 2 个分身，导致分身总量按 $2^n$ 呈裂变式暴增。
  3. **分身缺乏硬上限防护**：原 `Ninja_SpawnClone` 无任何存活数量检测，只要收到调用就无节制 `CreateUnit`，导致场上分身无上限膨胀。
  4. **预致死换体滥挂印记**：在 `DM_OnDamaged` 中，本体触发换体成功保命未死，但依然给攻击者施加了击杀 Karma 印记。
  5. **分身可被 A011 二次击杀转化**：原逻辑未对受害者做全玩家分身检测，导致击杀敌方分身也触发了击杀者的同化分身。
- **v2.9 彻底根治方案**：
  1. **分身绝不施加印记**：`DM_OnUnitDeath` 严格限定只有**无相真身 `H003` 本体真正死亡**时才向杀手施加一次性印记。分身（`u002`）和神尊（`u001`）死亡绝不施加任何印记。
  2. **废除双倍裂变，印记单体单次消耗**：每个因果印记被触发后立即从全局列表中彻底抹除；无论印记等级高低，每个印记触发时至多重生 1 个实体（真身阵亡则复活真身，真身存活则至多补充 1 个分身）。
  3. **实装 3/5/7 存活硬上限**：`Ninja_SpawnClone` 依据 `A011` 等级（Lv1/Lv2/Lv3 对应 3/5/7 个分身上限）强制执行上限拦截；生成前实时清理并统计存活数，一旦达到上限直接返回 `null` 拒绝生成。`A014` 神尊同样受限全场最多 1 个。
  4. **分身不可同化与死亡自爆**：引入 `Ninja_IsAnyClone` 判别全场任意玩家的分身实体。击杀任何分身单位**绝不能**触发 `A011` 同化新分身；分身死亡后立即 `SetUnitExploded` 爆碎且清除，不留尸体。
  5. **死亡事件防重入互斥锁**：引入 `udg_Ninja_DeathLock` 递归锁，彻底避免瞬时群体阵亡时的跨触发器嵌套重入。
  6. **换体存活不挂印记**：本体在 `DM_OnDamaged` 成功换体移魂继续存活时，移除了误挂印记逻辑。

## 9. 魔兽争霸III引擎避坑指南与开发铁律 (Golden Rules)

### 铁律 1：伤害监听事件严禁触发无限递归 (`udg_Strain_DamageLock`)
- **致命病灶**：在 `EVENT_PLAYER_UNIT_DAMAGED` 触发器中，一旦通过 `UnitDamageTarget` 造成额外反射伤害、溅射毒伤或雷击，该 API 会同步在当前线程再次派发 `DAMAGED` 事件！若没有锁，将引发灾难级的无限递归，导致魔兽直接 Fatal Error 崩溃。
- **铁律防护**：在入口处加入布尔锁，并在程序性伤害前后闭环加锁：
  ```jass
  if udg_Strain_DamageLock then
      return false
  endif
  set udg_Strain_DamageLock = true
  call UnitDamageTarget(...)
  set udg_Strain_DamageLock = false
  ```

### 铁律 2：`war3map.wts` 严禁出现未转义的多行字符串 (Single-Line Rule)
- 字符串表中单个 `STRING` 项内严禁出现物理回车换行，否则重制版加载界面会 100% 假死。所有换行必须在单行内以 `|n` 转义。

### 铁律 3：克隆体与分身严禁继承自 Hero 对象父类
- 任何战场伪英雄分身必须继承普通小兵父类（如 `ogru`），以避免英雄单位底层平分打怪经验的引擎缺陷。

### 铁律 4：`DialogAddButton` 严禁在 `0.00` 秒地图初始化时生成
- 必须通过单次计时器延迟至少 `1.00` 秒（参考 `TM_OnStartTimer`），待视口与 UI 渲染稳定后再行创建展示，防止按钮碰撞盒失效。

### 铁律 5：自动学习技能逻辑必须严格限定电脑 AI (`MAP_CONTROL_COMPUTER`) (v3.1)
- **致命陷阱**：在 `EVENT_PLAYER_HERO_LEVEL` 事件与英雄升级监听中，严禁未判断玩家控制者就直接触发 `AI_AutoLearnSkills` 或 `AI_ForceLearnSkill`，否则人类玩家升级时获得的技能点会被脚本瞬间强行代学，导致技能加点按钮彻底消失。必须在入口处与每个加点函数首行施加 `GetPlayerController == MAP_CONTROL_COMPUTER` 严格铁律门禁。

## 10. 二次开发指南：如何接入新英雄 (`H006`)

如需接入第 5 位自定义英雄（如 `H006`），请遵循以下标准流程：
1. 在 `factory_tpl/table/unit.ini` 定义 `H006`，并追加到四大种族祭坛的 `Trains` 字段。
2. 在 `factory_tpl/table/ability.ini` 中定义技能（如 `A031`~`A034`）。
3. 运行 `python tools/build_v13_objs.py` 编译对象并提取至 `payload/`。
4. 在 `payload/war3map.j` 中接入：
   - `DM_OnSpellEffect` / `DM_OnDamaged`
   - `AI_ForceLearnSkill` 加点映射
   - `AI_TacticalLoop` 电脑战术施法
   - `TM_ShowMainDialog` / `TM_ShowSlotDialog` 对话框选项（新增模式四：全部电脑出【万灵化身】`-m4`）
5. 用 `pjass.exe` 校验 0 错误后，运行 `do_rebuild.ps1` 打包部署。
